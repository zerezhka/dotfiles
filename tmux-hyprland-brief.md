# Задача: настроить tmux поверх Hyprland под многопроектный воркфлоу

## Контекст окружения

- ОС: Arch / EndeavourOS
- Window manager: Hyprland
- Терминал: (уточнить у пользователя, если не указан в dotfiles — например kitty/alacritty/foot)
- Shell: (уточнить, если не в dotfiles)
- tmux: пока не настроен / базовый конфиг, нужна полная сборка с нуля
- Редактор: neovim (используются vim-style bindings везде, где возможно)

## Проблема

Работаю параллельно над несколькими pet/рабочими проектами. На каждый проект открывается
несколько терминальных окон (редактор, запуск сервера, логи, git). В сумме получается много
отдельных окон Hyprland, раскиданных по workspaces — навигация становится неэффективной.

Пробовал группировку окон в Hyprland (`togglegroup`) — не подошло: группировка прячет окна
друг за другом как табы в одном месте, а не даёт быстрого переключения между разными
проектными контекстами. Легко теряется, какое окно активно.

## Целевая модель

Смещаю нагрузку по навигации с Hyprland на tmux:

- **1 tmux-сессия = 1 проект** (например: `cardkore`, `meme-search`, `data-reconciler`, `jomolungma`)
- **Windows внутри сессии = роли/задачи в проекте**: например `1-nvim`, `2-server`, `3-logs`, `4-git`
- **Panes (split) внутри window** — там, где нужно видеть два вывода одновременно (например лог + shell)
- Hyprland при этом держит по одному workspace на активный проект (условно 2-4 workspace вместо 15+ окон), а не по одному на каждый терминал

## Что нужно получить на выходе

### 1. `.tmux.conf`
- vim-style bindings для навигации между panes/windows (hjkl-style, а не default arrow-keys)
- удобный prefix (не обязательно дефолтный `C-b`, можно предложить альтернативу, но обосновать)
- быстрое переключение между windows по номеру
- быстрое переключение/создание сессий (session switcher — например через `tmux choose-tree` или fzf-based session switcher)
- вменяемый statusline: список активных сессий + текущее окно, компактно, без перегруза
- разумные дефолты: mouse mode вкл/выкл (на усмотрение, объяснить trade-off), history limit, escape-time (важно для neovim — минимизировать задержку)
- true color / поддержка 256color терминала

### 2. Плагины (через TPM — tmux plugin manager)
- `tmux-resurrect` + `tmux-continuum` — персистентность сессий между перезагрузками (важно: есть постоянно запущенные вещи — homelab-сервисы, к которым подключаюсь по ssh и делаю attach)
- при желании: fzf-based session/window switcher (`tmux-fzf` или аналог)
- statusline-плагин на усмотрение (например `tmux-power`/`catppuccin` — но не обязательно, минимализм предпочтительнее вычурности)

### 3. Хелпер-скрипт "session launcher"
Скрипт (bash/zsh), который:
- по имени проекта либо attach-ится к существующей tmux-сессии, либо создаёт новую с предустановленным набором windows (nvim / server / logs / git) в нужной директории проекта
- идея похожа на `tmuxinator`/`tmuxp`, но можно и просто самописный bash-скрипт — что проще встроить в текущие dotfiles, на усмотрение LLM
- должен быть легко биндится на shell-алиас или Hyprland keybind (`hyprctl` → `exec` терминала с этим скриптом)

### 4. Интеграция с Hyprland
- keybind в hyprland.conf: горячая клавиша открывает терминал с tmux session launcher (если нужного терминального окна нет — создать; если есть — сфокусировать)
- предложить: держать по одному Hyprland workspace на "область" (например workspace 2 = активная разработка, workspace 3 = мониторинг/логи), а не пытаться отражать структуру проектов в самом Hyprland
- НЕ использовать `togglegroup` — уже проверено, не подходит под этот паттерн

## Стиль/философия (важно учитывать при генерации конфигов)

- Минимализм, explicit over magical — не тащить лишние плагины и абстракции ради красоты
- Предпочтение hackable/прозрачных решений, а не "коробочных" тяжёлых фреймворков
- Готовность к CLI/keyboard-driven workflow, mouse — опционально и по минимуму
